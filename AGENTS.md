# AGENTS.md

Oviate: keyboard-first desktop charting tool (TradingView alternative). Linux first, portable design (core separated from UI).

## Stack
Tauri 2 + Rust core (`src-tauri/`) + Svelte 5/SvelteKit (SPA, adapter-static) + TypeScript (`src/`). Custom Canvas2D chart renderer (no charting lib). Pine engine in TypeScript.

## Commands (repo root)
- `npm run tauri dev` - run app
- `npm run check` - svelte-check. Read the whole output: errors are printed as `ERROR` (upper case)
- `npm test` - `node --test` (Pine engine, indicator library, strategies, paper engine) then `cargo test`
- `npm run tauri build` - bundle. `npm run tauri build -- --no-bundle` - release binary only (what the app-menu entry `~/.local/share/applications/oviate.desktop` launches; rebuild after changes, otherwise the menu app runs an old version)

## Layout
- `src-tauri/src/`: `lib.rs` (Tauri commands), `providers/` (alpaca, yahoo), `cache.rs` (SQLite candles, news, AI summaries, kv), `stream.rs` (Alpaca WebSocket), `news.rs` (news providers), `mcp.rs` (OAuth + MCP client for Liquid), `ai.rs` (Groq), `pine_files.rs` (user `.pine` files).
- `src/lib/chart/`: renderer, chart component, data transforms. `src/lib/pine/`: parser, interp, natives, ta, strategy, worker. `src/lib/paper/`: engine (pure, tested) and store. `src/lib/ai/pine.ts`: AI prompts, checks, repair loop (pure, tested); `cli/oviate.ts`: the `oviate` CLI (Node, node:sqlite on the app's `oviate.db`, same engine; `cli/oviate.test.ts`); `skills/oviate/SKILL.md`: the `/oviate` Claude skill (copied to `~/.claude/skills` by `scripts/install-local.sh`). Keep the CLI help and the skill in sync when commands change; `src/lib/pine/stats.ts`: detailed strategy statistics (pure, tested). `src/lib/ui/`: panels, dialogs, pages (news, script editor). `src/lib/app.svelte.ts`: global app state (persisted in the SQLite `kv` table).
- `logos/`: logo concepts; `logos/oviate-logo.svg` is the app logo (icons generated with `npx tauri icon`). `project-resume.md`: handoff file, keep updated and committed.
- `indicators/*.pine`: bundled indicators, seeded into `<app data>/indicators` on first start (a deleted one stays deleted). `strategies/` ships empty.

## Rules
- Rust core owns data providers, caches, news, keyring access and file storage. UI only renders and sends commands. Keep core free of Tauri types where possible.
- Every action must be reachable via keyboard / the command bar (`Enter`, `/commands`).
- Design: black, hard purple accents, 2px corners, no blur or backdrop-filter (WebKitGTK crashes/freezes on it), no native `<select>` (use `ui/Select.svelte`), no number spinners.
- WebKitGTK crash workaround: `src-tauri/src/main.rs` disables the AT-SPI accessibility bridge. Keep it.
- Chart navigation lives in `renderer.ts`: wheel input eases toward a target (`tgt`), hold-and-drag is applied once per frame in `applyPan()`, auto price range eases (`autoSm`). Wheel modes: Ctrl = joint zoom (`wheelZoom`, one factor for both axes), Ctrl+Shift = same with the hard right stop pinned to the right edge (the Reset chart framing; Shift turns the wheel into deltaX in WebKitGTK: use `dY || dX`), Alt = time stretch (`wheelBars`), Shift = price stretch, plain = time scroll (hands `manual` back to the eased auto scale). Right scroll limit is `RIGHT_PAD` empty bars after the newest candle (hard stop). Do heavy background work (ticks, polling, Pine reruns) only when `r.dragging` is false.
- No animations on dialogs (fade/pop caused a flash in WebKitGTK); all dialogs share one outline (`1px glass-line` + faint purple ring, no glow).
- Pine engine supports a v5/v6 subset: `request.security` is a passthrough, label/line/box drawings are accepted but not rendered.
- Pine extension `plot(..., pane="Name")` / `hline(..., pane="Name")`: one script can draw in several panes (`pine/panes.ts` `splitPanes`, used by `Chart.svelte` `active`); AI strategies put each oscillator in its own pane, `plotChecks` judges each pane separately. Tester slippage is percent of price per fill (`TesterSettings.slippagePct`, default 0.1, `Broker.slip`), not ticks; `strategy(slippage=)` ticks still work without tester override. The tester equity line is red as a whole when the result is below the starting capital, otherwise accent; the Equity scale hides the buy & hold lines, All lines shows both; Performance shows buy & hold over the whole period and over the invested time only (`stats.ts` `investedMove`).
- Optimizer: `pine/optimizer.ts` (pure: pattern search with step doubling, recency-weighted segment metrics, 3 category winners + 7 profiles, neighbour robustness, Fast<Slow ordering via `orderedPairs`), run in `pine/optimizer.worker.ts` via `optimizer-runner.ts`; state/apply in `optimizer.svelte.ts`, UI `ui/OptimizerPanel.svelte` (tab in `PaperPanel`), candles via `chart/candleStore.ts`; CLI `oviate optimize`. Change scoring only in `optimizer.ts` and keep README, CLI help and the skill in sync. Tester fills market orders at the signal-bar close by default (`TesterSettings.fillOnClose`, `Broker.fillMarketOnClose`; paper-trading signals run with it off because they act on pending orders).
- Code editor (`ui/ScriptEditor.svelte`): `app.editor.blank` = nothing selected (`/ind`, `/strat`), `name: null` = new script. For strategies a params bar (size, stop loss %, take profit %) is always shown above the code and edits it through `setStrategyParams` (no AI; the form mirrors the code via an effect). Settings need no AI: size via `setPositionSize`, stop loss / take profit via `setStrategyParams` (adds `oviSl`/`oviTp` inputs + `strategy.exit` block if the code has none), direction via `setDirection` (`allowLong`/`allowShort` input.bool + `when=` on the entry calls, `readDirection` reads it back). The file name and the script title are one name (`ScriptEditor` keeps them in sync). Builder from code: `aiBuilderFromCode` (LLM) reads non-builder Pine into the builder; `builderModelOf` only trusts the `@oviate-builder` model while the generated conditions are unchanged. The AI button edits the open script via `editIndicator` / `editStrategy` in `ai/pine.ts` (same checks as generation, plus a no-op check); the strategy form is read back from the code by `extractStrategyForm`. Optimizer category winners are chosen on the visible raw figures; do not switch them to the recency weighted ones.
- Visual builder: `src/lib/builder/model.ts` (pure, tested: model, `toPine`, `parseModel`, `checkModel`, `suggest` = per-indicator ideas), `builder/ai.ts` (text -> model JSON, validated, repair rounds), `builder/info.ts` (IndInfo of library indicators via `describeScript`), UI `ui/BuilderPane.svelte` (conditions) + `ui/OperandPicker.svelte`; it is a view of the code editor (`ScriptEditor.svelte`: Builder / Editor toggle replaces only the code area; the settings row with size, SL, TP, direction, AI text + send button stays; `app.openBuilder(name)` / `/visual` open the editor with `app.editor.builder`). In builder mode the settings row edits the model, SL/TP apply to both sides, direction switches the sides on or off. Generated strategies read library indicators with the Oviate extension `oviate.ind("file name", "Plot title", "Input=value;...")` (`pine/indlib.ts` registry + native in `interp.ts`; workers get the needed sources via `RunOptions.lib` / `neededLib`; the CLI reads `<data>/indicators`). Every condition is computed into its own variable each bar (never inside `and`/`or`) so `ta.*` state stays correct. Builder code is regenerated from the `@oviate-builder` JSON comment on save.
- Chart sync (`renderer.ts`): all on-screen renderers are in a module-level `live` set. With `chartSync.on` (app.sync) one chart leads (`chartSync.leader` = the one the user touched last, set on pointerdown / wheel / `viewChanged()`); at the end of its draw `pushView()` hands every other chart the time window plus its price range as multiples of the last close, so all charts show the same time and the last-price line at the same height (followers run with a manual range, `releaseFollow()` when sync is off). Charts that load or mount call `followLeader()` instead of resetting. Crosshair via `setExternal`; no reactive round trip. Replay is shared in `app.replay` (owner, t, playing, speed): with sync on every chart is cut at `t`, else only the owner. Canvas resize repaints synchronously (no blank frame).
- Calendar: Rust `calendar.rs` (`window()` is the whole data flow and is covered by an ignored live test; `calendar_summary` command + `ai::CalSummary` for the Groq reading, cached per event / language / actual) (macro: Forex Factory weekly JSON keyless, FMP with key `fmp_key`, cached in kv `calendar`, hourly; companies: Nasdaq `api.nasdaq.com` earnings / dividends / splits per weekday and IPOs per month, keyless, cached per day in kv `cal_nq_<date>` / `cal_ipo_<month>`; `CalEvent.kind` = macro | earnings | dividend | split | ipo, `symbol`, `detail`) -> `calendar_window` command (returns the cache at once; missing company days are fetched by `calendar_refresh` in the background, nearest first, `CalendarResult.pending` makes the UI ask again every 2-3 s) -> `calendarWindow` in `api.ts`; UI `ui/CalendarPage.svelte`, chart markers `CalMark` in `renderer.ts` (`drawCalendar`, hover tooltip, `onCalClick`), `app.openCalendar(id)` / `app.calFocus` open the page on one event. Event ids must stay unique (the list is keyed by them: a duplicate key used to blank the whole page); `window()` dedupes with a HashSet. In browser preview mode `api.ts` returns synthetic events.
- Builder model v2 extras (`builder/model.ts`): operands `time`, `sess`, `hl`, `pos` and `ago` / `pct`, comparisons `between` / `at_least` / `at_most` / `equal` / `not_equal`, side `maxPerDay`, model `tz`; generated Pine uses `oviate.hhmm/dow/date(tz)` and `var` accumulators. Each condition is its own variable.
- Symbol regions (which macro currencies a chart shows): `src/lib/regions.ts` (`knownCurrencies`: pair / crypto / index / exchange-suffix rules, then the bundled table `data/symbol-regions.json` of the ~1500 largest US-listed stocks built by `scripts/gen-symbol-regions.mjs` from the Nasdaq screener; rerun it to refresh), unknown symbols -> backend `symbol_regions` (`regions.rs`: kv cache `symreg_<SYM>`, Nasdaq company profile country, else Groq) -> `app.symRegions`; default USD until resolved. Country rule is duplicated in the script and `regions::country_currencies`: keep in sync.
- Calendar providers: Forex Factory 429 -> kv `cal_ff_until` cooldown (1 h; others 5 min) and the cached macro events stay; FMP 401/402/403 -> kv `fmp_until` 24 h block plus a dim hint on the page; manual refresh at most every 5 min. The calendar list is anchored on the next upcoming event (or the event opened from a chart marker, `anchorId`) at the top under the sticky day header; it re-anchors when data arrives until the user scrolls (`userScrolled`); ranges are only ±7 / ±14 days. Tester equity legend: toggles per line + scale switch, state in `app.eqView` (persisted; buy & hold lines off by default), see `PaperPanel.svelte`. Main layout: the bottom `PaperPanel` is outlined like the panes (`margin: -1px 0 12px 12px`, grid bottom padding 0). Tester equity scale "equity": own range, widened by at most 0.6 of its span for the buy & hold lines (cut off beyond that, hint shown); "all lines": one scale holding every shown line.
- Chart markers (news, calendar): square 14px tags, no glow; `declutter()` keeps only the highest-priority marker where they would overlap (calendar by impact, news by count) and zooming in brings the rest back; hit-testing uses the same visible set. News windows are re-checked every 5 minutes (Chart, window focus, NewsPage every 3 minutes); calendar: backend TTL 1 h for today and the next 2 days, UI every 5-10 minutes and on focus; Nasdaq requests have a 12 s timeout.
- Control heights: form controls 30px (`box-sizing: border-box`), top bar buttons 32px; audit new rows for equal heights.
- Main page layout: panes touch (grid gap 0, borders collapse) and the pane / panel border lines are the drag handles (invisible hit zones in `+page.svelte`, no highlight line).
- Replay (`Chart.svelte`): `app.replay.t` = time of the last visible bar, `view` = raw candles cut there (zero-copy subarrays), everything downstream (renderer, Pine, tester) uses `view`; polling, ticks and paper live signals are paused while replay is on. The renderer only handles the scissors pick (`replayPick`, `onReplayPick`). Arrow path (`arrowpath`): multi-click draft in `renderer.ts`, finished by `finishPath()` (Enter, Esc, double click). Zoom limits: `BAR_MIN` 0.03; `wheelZoom` clamps time and price independently.
- Scripts added from outside the app (CLI) appear when the window gets focus (`library.load()` on `focus`).
- AI code generation: Rust `ai_complete` command (OpenRouter free models, `ai::CODE_MODELS` fallback chain, key `openrouter_key` in keyring; Groq stays for news summaries only) is a plain chat call; prompts, repair loop and validation live in `src/lib/ai/pine.ts` (see the pipeline entry above).
- AI pipeline (`src/lib/ai/pine.ts`, pure, tested with a mock completer): `genIndicator` and `genStrategy` = system prompt (v6 rules, from `Syspromptvorschlag.md`; strategy prompt explains next-bar fills, strategy.exit, one-time indicator computation, two verified reference strategies) + similar scripts as few-shot -> run-time checks (`sanity` for indicators, `strategyCheck` on `STRAT_SAMPLE` for strategies: errors, never trades, wrong direction, missing SL/TP exit, scale) -> up to 4 repair rounds with the error fed back. The position size of the form is forced into `strategy()` by `setPositionSize`, never trusted to the model. One model call per round (free models are rate limited: Rust retries 429, then falls to the next model). Extend checks/prompts there, not in the UI.
- Trading journal: bottom panel tab `journal` (`ui/JournalPanel.svelte`, pure logic + tests in `paper/journal.ts`): per paper account, trades newest first (green / red rows, plain green/red not the theme up/down colours), filters, calendar by day / week / month, per-trade notes (`ClosedTrade.note`, `paper.setTradeNote`). Command bar entry `Open Trading Journal`.
- Back / forward: `lib/history.ts` (pure, tested; entries with undo / redo, same-key pushes within 600 ms merge). `+page.svelte` records one snapshot of every navigable view (see the Keybinds entry) and handles Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y and mouse buttons 3 / 4; `Chart.svelte` `onDrawings` records drawing edits. Chart performance: `raw` and `pineResults` in `Chart.svelte` are `$state.raw` (no proxies in renderer hot loops); below 1.5 px per bar candles are drawn per pixel column (`drawDenseCandles`), plot lines below 1 px per bar one point per column, shapes are skipped below 1.2 px. Strategy on a paper account: wallet button in the chart pill (`ind.account`). Text selection colour is global in `+page.svelte`.
- Keybinds: `lib/keybinds.ts` (pure, tested: `comboOf`, built-in actions with defaults, overrides in `app.keybinds`, `assign` takes a combo from other actions), `lib/commands.svelte.ts` (`buildCommands`: command-bar commands with stable ids, editable text in `app.cmdAlias`), UI `ui/KeybindsDialog.svelte` (`app.keybindsOpen`). New keyboard actions must be added to `BUILTIN` and checked with `hasCombo`, never with raw `e.key`. Back / forward snapshot (`+page.svelte` `Nav`) must include every new navigable view state (put it in a store, not component-local state). Builder conversions: `builder/cache.ts`; `app.editorMode` (code / builder) is the remembered editor view. Ctrl+Shift+wheel pins the hard right stop; `resize()` keeps the newest bars at the right edge and synced followers re-apply the leader window.
- Layout reduction (`app.setLayout`): the marked chart stays, then the most recently touched ones (`app.noteTouched`), moved to the front slots. Candle fetch (`get_candles` in `lib.rs`): one fetch at a time per symbol + timeframe, Yahoo retries transport errors / 429 / 5xx, and a failed tail refresh serves the cached candles instead of an error.
- AI routing: `ai_complete` (OpenRouter) for Pine code, `ai_complete_light` (Groq first, OpenRouter fallback) for the builder tasks via `aiLight` in `api.ts`. Back / forward also records `Select.svelte` picks and committed field changes (`change` events, `data-nohist` opts a field out); history pushes during a step are ignored and a step returning `false` is skipped. Synced followers show exactly the leader's dates at the left and right edge (span measured in the follower's own bars via `timeToIdx`), so the same date sits at the same relative position on every chart; only the follower's own scroll limits (`clampStartV`, which also caps the empty space at the right to RIGHT_PAD bars) can pull it back, e.g. when its data ends much earlier. Dev builds expose the chart set as `globalThis.__ovLive` for browser tests. Candle refresh waits at most 4 s before showing the cache.
- Synced followers (`applyView`) always clamp the result to their own scroll limits (`clampStartV`): no chart may scroll past its data, whatever the leader does.
- Paper trading commission is charged per fill (buy and sell each), as percent of trade value.
- Test scope (Strategy Tester + Optimizer): `lib/universe.ts` (pure, tested: `Scope` = years / count / tf, 0 and 'chart' = what the chart has; `UNIVERSE` = 200 securities listed 10+ years, interleaved strong / mid / weak 10-year performer so any first N is mixed; `scopeSymbols`, `scopeFrom`), state `app.scope.tester` / `.optimizer` (persisted), bar `ui/ScopeBar.svelte` above the equity chart / under the optimizer header, candles `scopeData.ts` `loadScope` (`getCandles`: SQLite cache, missing ranges fetched from Alpaca / Yahoo, 4 parallel; Yahoo limits intraday history, the tester header warns when less than asked came back). Chart scope = unchanged live path (`app.strategyResults`, the chart keeps drawing its last 20 trades whatever the scope is). Other scope = separate run in `tester.svelte.ts` `testerRun` (Run button, per-security table, `universeSummary` in `pine/stats.ts`, selected security feeds the usual overview), never touches the chart. Optimizer: `optimize({ data: PineCandles | PineCandles[] })` runs every test on all securities, `mergeMetrics` pools trades and averages the rest (`breadth` = share of securities with a positive return). The tester overview shows a data line (symbol, tf, date range, bars, slippage, fees, fill mode).
- Tests: Node runs TypeScript by type stripping, so test-covered files must avoid parameter properties and enums, and use `.ts` import extensions.

## Secrets
Alpaca, Finnhub, NewsAPI, Groq keys and Liquid tokens live in the OS keyring only. Never in repo, logs, commits, `.env.example` values. Liquid OAuth requests the `read` scope only, never `trade`. Paper trading only, no live orders.

## Local install (always)
The newest version of Oviate must always be installed on the user's computer. Right after every push to `main`, run `scripts/install-local.sh` (about 4 min, run it in the background) so the app-menu entry launches the new build, then tell the user to restart Oviate. Also do it whenever the user says the installed app lacks a feature.

## Git
Push directly to `main`. No PRs unless asked. Commit `project-resume.md` with every change. If `git push` fails with an invalid token, push once with `git -c credential.helper= -c "credential.helper=!gh auth git-credential" push origin main`. Commit messages end with the Co-Authored-By line from the session.
